CRAVE Counterfactual Value Learning for Budgeted Language Model Agents
Matched interventions and resource allocation in multihop question answering
Author names and affiliations to be supplied
Method and empirical pilot study   October 2026
Abstract
Language model agents allocate inference resources among reasoning, retrieval, verification, and stopping. We present CRAVE, a controller trained on matched interventions from identical intermediate states to estimate policy-conditioned downstream utility. A frozen encoder and a compact neural controller predict action values and future resource use, while a feasibility mask enforces hard budgets. Four training questions produced 156 branch records. An initial six-question pilot was followed by a frozen-controller evaluation of 40 fresh questions from bounded HotpotQA and 2WikiMultiHopQA pools, yielding 480 episodes across three seeds and four methods. At a 512-output-token budget, CRAVE achieved 55.0% and 43.3% normalized exact match, versus 50.0% and 46.7% for a confidence rule. Paired accuracy differences were +5.0 percentage points (95% question-bootstrap interval 0.0 to 15.0) and −3.3 points (−10.0 to 0.0); both Holm-adjusted permutation p values were 1.0. CRAVE used 229.5 versus 51.2 and 249.7 versus 60.1 output tokens. Additional token costs were 178.3 (149.1 to 203.9) and 189.6 (165.9 to 211.4), with adjusted p = 0.0018 in both datasets. Repeated reasoning calls accounted for the additional generation. The accuracy differences each depended on one question. Audits found zero budget violations. CRAVE provides an executable framework for matched action valuation, but this small post-pilot study establishes no efficiency advantage over confidence. The public numerical release supports reconstruction of the reported analyses.
Keywords   Language models; inference budgets; counterfactual branching; adaptive retrieval; verification; resource allocation
1 Introduction
A language model agent can often improve an answer by generating another reasoning step, retrieving a missing fact, or checking a candidate. Each operation also consumes resources and can introduce new errors. The practical allocation problem is therefore sequential: the usefulness of an action depends on what the agent already knows, what it has tried, and which resources remain. Retrieval-augmented generation combines parametric knowledge with external evidence [1], while ReAct interleaves reasoning and environment actions [2]. These capabilities create a choice about when and how much to use each resource.
Budget awareness and adaptive stopping already have substantial precedents. BudgetThinker conditions reasoning on remaining token capacity [3]. PUMA uses semantic redundancy and answer verification to identify candidate stopping points [4]. Confidence-based adaptive scaling couples confidence calibration with computation allocation [5]. TARG gates retrieval from a short retrieval-free draft [6]. These methods show that adaptive allocation is an established research area; adding a budget feature or a confidence threshold alone is insufficient to support a new contribution.
The specific question studied here is whether a small controller can learn a comparable long-horizon value for several heterogeneous actions at the same intermediate state. A retrieval step may not immediately produce an answer but may make the next reasoning step useful. Verification may preserve a correct answer or replace it with an incorrect one. Additional reasoning may use evidence effectively or repeat an existing conclusion. A controller trained only on immediate rewards can miss these delayed consequences. A controller trained on observed trajectories alone may lack outcomes for actions that its collector rarely selects.
CRAVE addresses these issues with controlled interventions within a fixed executor. For each recorded state, we restore the same state, force an eligible action, and execute a shared continuation policy. The resulting action values refer to that continuation policy and that executor. They are not policy-invariant causal effects or guaranteed values under the deployed controller. This distinction is central to the method and to the interpretation of its results.
We study whether matched downstream supervision can support a shared controller for heterogeneous inference actions. The contribution is an executable formulation and a transparent empirical test at one operating point. The initial pilot checks the learning and accounting machinery; a separate frozen-controller evaluation tests whether its behavior persists on fresh questions. The latter finds additional output consumption without a significant accuracy improvement over a confidence rule. This result motivates a precise distinction between enforcing a budget and allocating that budget effectively.
1.1 Contributions and scope
CRAVE defines matched supervision for heterogeneous agent actions at a common saved state, including terminal answer reward and future resource consumption under a declared continuation policy. It combines utility, success, cost, ranking, and ordered-interaction objectives in a small controller without updating the language backbone. The release exposes question-level outcomes, paired uncertainty, action counts, and cost components alongside an independent reconstruction audit. The contribution concerns formulation, implementation, and a diagnostic evaluation; no result establishes that individual loss terms or counterfactual labels improve efficiency.
2 Related work
2.1 Budget control and stopping
BudgetThinker introduces control tokens and training procedures that make reasoning responsive to token limits [3]. PUMA identifies redundant reasoning and verifies proposed exits [4]. CAS uses calibrated confidence to allocate additional samples [5]. Their action families and supervision differ from CRAVE, but they constrain the novelty claim: reasoning length, answer readiness, and remaining budget are already useful allocation signals. The pilot confidence comparator is a fixed threshold rule over one candidate answer. It does not reproduce the calibration training and answer aggregation of CAS. Likewise, the implementation does not claim to reproduce the full PUMA protocol.
2.2 Retrieval and heterogeneous actions
TARG treats retrieval as a query-level decision derived from a no-context prefix [6]. DeepControl regulates information acquisition through retrieval continuation and granularity control [7]. Inference-Time Budget Control chooses search actions under token and tool limits using an operational value-of-information score and selective answer finalization [8]. These methods make adaptive information acquisition and heterogeneous budget accounting close prior work. CRAVE treats the retriever as a fixed module and asks how its estimated downstream return compares with reasoning, verification, and stopping at intermediate states.
2.3 Counterfactual tool boundaries
CoBRA learns the margin between internal and external tool-assisted experts using paired trajectories [9]. Its relevance is especially direct because the comparison is counterfactual and uses Qwen3-4B. CRAVE proposes repeated multi-action valuation within a trajectory, with common state restoration, explicit future resource costs, and auxiliary ordered interactions. This is a methodological distinction, not evidence that CRAVE outperforms CoBRA. None of these official systems was reproduced or evaluated in the completed pilot. Establishing comparative novelty and performance requires faithful implementations under a matched protocol.
2.4 Adaptive computation and sequential learning
Adaptive Computation Time learns how many recurrent computation steps to use [16], and PonderNet learns an adaptive halting distribution [17]. These establish learned computation allocation as an older principle. CRAVE applies value estimation to externally executed reasoning and tool actions while retaining a frozen language backbone. It does not learn an internal halting mechanism or reduce backbone training cost. Self-consistency samples multiple reasoning paths and aggregates their answers [20]; this is a distinct way to spend inference computation. The implemented confidence rule does not perform that aggregation, so these results do not compare CRAVE with self-consistency.
DAgger addresses the shift between training states and states induced by a learned sequential policy through iterative data aggregation [18]. CRAVE shares the motivation for collecting states under a changing controller, but its two collection rounds supervise branch returns under the same fixed continuation μ0. This procedure does not inherit DAgger guarantees and does not remove the mismatch between label continuation and deployment policy.
2.5 Retrieval context and uncertainty
Self-RAG trains a language model to retrieve and critique using reflection tokens [19]. CRAVE instead trains a separate small value controller over a frozen language model and retriever. Lost in the Middle shows that access to relevant long-context information need not ensure its effective use [21]. This distinction matters here because passage-title recall and answer correctness measure different parts of the system; the retrieval proxy cannot establish reasoning success.
Calibration concerns whether numerical confidence corresponds to correctness frequency [22]. Semantic entropy estimates uncertainty over meanings across sampled generations [23]. CRAVE uses a single verbalized confidence field and summary similarity as inexpensive monitoring features. Neither feature implements semantic entropy or establishes calibrated uncertainty, and the finite-K diagnostic proportions cannot replace a sufficiently sampled calibration study.

3.1 Observable state and actions

The action set is A = {THINK, RETRIEVE, VERIFY, STOP}. THINK generates a candidate and a short public summary. RETRIEVE obtains additional passages. VERIFY checks the current candidate against available evidence using a separate instruction to the same model. STOP returns the current candidate without another answer-generation call. Verification has a distinct prompt, but its errors need not be independent of reasoning errors because the backbone is shared.
Summaries and capped evidence are lossy representations of an evolving interaction. We therefore use an observable-state control formulation; we do not prove that the representation is a sufficient Markov statistic. The environment is finite because hard resource limits and a maximum of twelve nonterminal steps bound each rollout; an additional STOP action can terminate at that limit. STOP is always eligible and can return an empty candidate; an empty output scores zero under the answer metric.

The executed budget was 512 generated tokens, one retrieval call, and one verification call per task. Latency was measured but not enforced as a hard deadline. A certified timeout executor would be required for a hard latency guarantee; the current environment explicitly rejects configurations that request one. Thus, the pilot does not implement every budget dimension of the broader proposed study.

4 Matched counterfactual branching
4.1 Restoration and randomized continuations
A checkpoint serializes the complete observable state, resource counters, seed, step, and action log. Its content hash is verified on restoration. For each eligible intervention, the executor restores a fresh copy and checks equality with the pre-intervention checkpoint before assigning a randomized branch seed. Each replicate uses a seed derived from the recorded checkpoint hash, collector seed, and replicate index. Replicate seeds are common across alternative actions at that checkpoint, reducing unnecessary differences in randomization.
The base backend receives an explicit, stateless prompt. Its internal token cache can accelerate repeated prefixes, but it does not add conversation information beyond that prompt. The inference state contains no gold answer, aliases, supporting-fact annotations, reward, or oracle action. Such fields remain in offline scorer records. Visited states are saved before their branches are generated, so resumption reuses the recorded intervention state instead of creating a new state with slightly different measured timing.

K was fixed at three for this pilot. A completed stability study would compare this choice with larger K on development tasks. Sample utility means, success means, and normalized cost means are targets; they are noisy estimates rather than exact values. Checkpoint identity is necessary for the matched interpretation, but it does not eliminate sampling variance or the dependence on μ.
4.2 Label policy and visitation aggregation
The bootstrap continuation μ0 assigns weights 0.35 to THINK, 0.35 to RETRIEVE, 0.20 to VERIFY, and 0.10 to STOP, renormalized over eligible actions. The STOP weight is reduced to 0.02 when no candidate exists. Policy randomness is reproducible from the state seed and step. The same μ0 was used to generate branch labels in both collection rounds.
Round one visits the initial state and a state after THINK for each training task. A controller fitted to these labels then influences round-two visitation through a mixture that selects μ0 with probability 0.3 and the learned controller otherwise. A terminal decision can leave only an initial recorded state. The observed state counts were eight in round one and seven in round two. Changing visitation while keeping the label continuation fixed avoids silently changing the value estimand between rounds.
The pilot produced 156 matched branch records and 111 records from naturally selected observational trajectories. Records from ordered pairs and empty interventions are included in the branch total. These counts are not 156 independent training tasks: the underlying questions number four, and several branches share a checkpoint and common replicate seeds. All learned controllers were trained only on training-split records.

Jμ(z) denotes expected utility at the same state and utility weight after forcing the sequence z and then following μ. The empty sequence ∅ proceeds directly with μ without a forced action. Single-action J values coincide with the corresponding policy-conditioned Q values.
Only replicate indices shared by all four intervention families enter the contrast. An ordered pair that becomes infeasible is excluded for the affected sequence. These contrasts depend on the continuation regime and on feasibility; they are not additive decompositions of a trajectory reward. The controller uses them as auxiliary shared-trunk supervision. They are not added again to the selected Q value, because the single-action return-to-go already includes downstream consequences. Interaction supervision was limited to one selected checkpoint per collection round, so broad complementarity claims are untested.
4.4 Guarantees and estimation limits
Resource compliance follows by induction under the implemented executor assumptions. Initial hard budgets are nonnegative. Before each nonterminal action, the mask requires a reservation at least as large as the maximum charge for every constrained resource. Actual charges are nonnegative and no greater than those reservations, so subtraction preserves nonnegative remaining budgets. STOP incurs no constrained charge and remains available. The finite step limit permits a final STOP. This establishes compliance for output tokens, retrieval calls, and verification calls when the backend respects its caps; it does not guarantee a latency deadline, answer correctness, or useful allocation.
Matched randomness has a conditional variance benefit. For replicate returns U(a) and U(b) at one checkpoint, Var(Qhat(a) − Qhat(b)) = [Var(U(a)) + Var(U(b)) − 2 Cov(U(a), U(b))] / K when replicates are independent across replicate indices. Common random seeds can increase positive covariance and reduce contrast variance, but the covariance need not be positive after different interventions. Common seeds therefore support controlled comparison without guaranteeing lower variance. K = 3 gives limited resolution; branch records sharing a checkpoint are not independent training tasks.
A conditional action-selection bound clarifies continuation mismatch. If every feasible learned value differs from Q under μ0 by at most ε, the loss relative to the best feasible μ0 action is at most 2ε: compare the true value of the best action with its prediction, apply predicted argmax optimality, and compare the selected prediction with its true value. If values under deployment continuation π differ from μ0 values by at most δ for every feasible action, the corresponding one-decision loss under π is at most 2ε + 2δ. This bound does not establish an optimal full policy. Neither ε nor δ was estimated, so it cannot provide a numerical performance certificate.
5 Controller architecture and optimization
5.1 Features and prediction heads
The frozen all-MiniLM-L6-v2 encoder supplies 384-dimensional masked-mean-pooled and L2-normalized vectors [14]. Four vectors encode the query, the last three public summaries, accumulated evidence, and the candidate together with verification text. Encoder inputs are truncated at 256 tokens. Thirteen scalar features represent normalized remaining token, retrieval, and verification budgets; raw verbalized confidence; semantic convergence; evidence sufficiency; retrieval novelty; normalized step; utility weight λ; and a four-way previous-action indicator. The resulting input dimension is 1549.
Confidence is the bounded value verbalized by the base model, not a calibrated probability. Convergence is summary embedding similarity. Novelty compares the embeddings of previous evidence and newly admitted evidence. Evidence sufficiency uses the bounded model support signal and is zero in the absence of evidence. These inexpensive proxies are operational definitions rather than validated measures of latent uncertainty or factual support.
A two-hidden-layer ReLU multilayer perceptron has widths 512 and 256 and forty outputs. For each of four actions, six outputs encode Q, a success logit, and four future-cost logits. The success output is transformed by a sigmoid, and costs by softplus. Sixteen additional outputs represent ordered interaction contrasts. The base language model and encoder remain frozen; controller training uses NumPy analytic gradients and Adam on the CPU.
5.2 Joint supervision
The Q head uses Huber loss. The success head uses squared error against finite-K success proportions. Each resource head uses Huber loss against its normalized future cost. The four auxiliary weights were fixed at 0.25. Adam used learning rate 0.001, batch size 64, one hundred epochs, gradient norm cap five, and seeds 17, 29, and 43. These defaults were not selected through development optimization.
The training utility weights were 0, 0.05, 0.1, 0.25, 0.5, and 1.0. This gives the value predictor an explicit preference input, but it does not establish successful interpolation or generalization across preferences. Deployment evaluation used only λ = 0.1. A broad preference frontier cannot be inferred from this single operating point.

6 Experimental protocol
6.1 Data and split boundaries
HotpotQA supports multi-document factual and comparison questions with supporting facts [10]. MuSiQue composes connected single-hop questions into multihop tasks [11]. 2WikiMultiHopQA supplies reasoning-oriented questions and structured evidence [12]. The original feasibility run used small first-record subsets, rather than random samples or full benchmark releases. They were chosen before model evaluation to make execution and audit feasible.

The expanded test was selected separately after the original pilot. Its forty questions are disjoint from the other roles in Table 1; Section 7.6 provides the frozen selection and evaluation protocol.
HotpotQA records were obtained through the public dataset-server representation of the HotpotQA distractor data. MuSiQue training and development records, and 2Wiki development records, came from public raw exports linked by the MuSiQue authors. The subset files retain URLs and checksums. These raw exports are not asserted to be identical to complete official release files. The exact linkage between the dataset-server snapshot and the recorded repository revision also requires further verification for a definitive study.
Task IDs, normalized questions, and available component-question identifiers were checked across partitions. The reserved development set was not used for threshold, K, hyperparameter, or loss-weight tuning in this run. The six evaluation tasks were excluded from learning and label aggregation. The 2Wiki tasks were absent from controller training, but this narrow transfer check does not establish out-of-domain robustness.
6.2 Executor and corpus
All compared policies use the official Qwen3-4B Q4_K_M GGUF checkpoint through llama.cpp release b11146 [13, 15]. Sampling uses temperature 0.7, top-p 0.8, and top-k 20. The executor requests bounded structured answers and public summaries in non-thinking mode. THINK permits at most 256 output tokens and VERIFY at most 192. This practical operation differs from unconstrained hidden-chain-of-thought continuation; results apply to this specified executor.
The original feasibility corpus pools all 300 unique passages supplied by the selected training, development, and evaluation records, without reading supporting-fact flags or answers during corpus construction. Retrieval combines BM25 and frozen dense cosine rankings with reciprocal rank fusion constant sixty. Each RETRIEVE returns up to five documents. Newly admitted passages are capped at 280 tokens each and total added evidence at 1400 tokens. The query uses the question and the most recent available summary.
Pooling supplied evaluation passages is a transductive benchmark-context setting. It is substantially easier and smaller than open retrieval over a full Wikipedia snapshot. The same pool is available to every policy, but corpus availability still limits external validity. The separate support-title evaluation reads gold annotations only after retrieval and never sends them to the agent.
6.3 Comparators and ablations
The fixed schedule requests RETRIEVE, THINK, VERIFY, THINK, and STOP, skipping masked actions. The confidence rule retrieves when no evidence exists, reasons while resources permit, and stops when a candidate has verbalized confidence at least 0.8. The LLM router uses the same backbone to select a permitted action in at most twenty-four output tokens; it reserves routing cost before executing that action. These are transparent in-house controls, not reproductions of named literature systems.

6.4 Metrics and statistical unit
Answer exact match and token F1 use normalized strings and available aliases. For the raw exports, equivalence to each released benchmark evaluator and its complete alias mapping has not been established. Thus, the reported scores are pilot normalized answer metrics, not official leaderboard scores. Supporting-fact exact match or F1 is not reported as a task outcome.
Results average the three seeds within each question before averaging questions. Bootstrap intervals resample task clusters with ten thousand draws. Paired tests operate on task-level differences and use exact sign permutations for these three-question dataset cells. Holm correction was applied across twenty-eight exploratory dataset, comparator, and metric comparisons. Seeds and episode rows are not treated as independent questions. With three task clusters per dataset, inferential resolution is extremely coarse. The resampling framework follows the bootstrap principle [24], and the multiple-test adjustment follows Holm [25].
Raw output, input, and total tokens; retrieval and verification calls; logical latency; controller latency; and normalized composite cost are recorded. Cached generation results retain their original observed model latency for logical accounting, while physical request counts record work actually performed. Encoder caching, slot behavior, and action overhead prevent these logical times from being interpreted as a standardized cold end-to-end latency benchmark.

OpenAI Codex with a GPT-6 family model assisted implementation, verification scripts, literature synthesis, manuscript drafting, and Matplotlib plotting code. Empirical plots are computed from saved numerical records; no image-generation model supplied result values or research images. The method schematic is a programmatic drawing. 7.1 Answer quality and generated output cost

CRAVE obtained exact match 0.3333 on HotpotQA and 0.6667 on 2Wiki. The confidence rule and fixed schedule obtained the same exact match. F1 equaled exact match for every method in this pilot. The LLM router returned no correct HotpotQA answers but matched the other retrieval policies on 2Wiki.

CRAVE used 207.3 generated tokens per HotpotQA task compared with 62.4 for the confidence rule, and 262.6 per 2Wiki task compared with 51.3. These ratios are approximately 3.32 and 5.11. The confidence rule therefore attained the same observed answer quality with lower output consumption in both dataset cells. No efficiency gain over that comparator is visible at the evaluated setting. This observation does not prove that the method cannot improve with adequate training or a different prespecified setting.
Each nonzero accuracy cell has a task-bootstrap 95% interval spanning 0% to 100%. This reflects the small number of task clusters and the coarse binary outcomes. The paired accuracy difference between CRAVE and the confidence rule is exactly zero on the observed questions, giving a degenerate [0, 0] bootstrap interval for that difference. Neither interval addresses representativeness of first-record samples.

7.4 Held-out value diagnostics
A separate analytical oracle branched from three held-out HotpotQA states after THINK, with K = 3 under μ0. Oracle labels were used only for diagnostics. Table 6 averages seed-level summaries at λ = 0.1. Regret is the finite-K empirical maximum utility minus the empirical utility of the action preferred by the learned Q head. Top-one agreement uses the same empirical maximum and its deterministic tie handling.
Table 6  Finite K held-out action-value diagnostics on three states

CRAVE mean regret was 0.0409, lower than −CF at 0.0652 but higher than −RTG at 0.0000 and −Interaction at 0.0226. Its top-one agreement was 44.4%. This pattern does not establish the intended return-to-go or interaction advantages. Indeed, the immediate-target model agrees with the empirical oracle on these states despite having zero answer accuracy in deployment. The diagnostic states have little measured opportunity for a successful continuation, so preferring inexpensive termination can score well in that limited diagnostic. Local oracle agreement and full task performance answer different questions.
The success MSE is measured against finite-K success proportions, not individual Bernoulli outcomes. It omits the irreducible within-action success variance that an ordinary per-outcome Brier score would include. ECE likewise bins predictions against noisy finite-K proportions. These descriptive calibration proxies must not be reported as unbiased population calibration estimates. With K = 3, empirical utility maxima can be optimistic and action rankings unstable.

7.6 Expanded frozen controller evaluation
After inspecting the feasibility pilot, we froze an expanded evaluation with twenty new HotpotQA questions and twenty new 2Wiki questions. A NumPy generator with seed 20261005 sampled without replacement from 131 eligible HotpotQA and 125 eligible 2Wiki candidates. IDs, normalized question strings, and available component-question identifiers were disjoint from training, reserved development, and the original evaluation. The candidate pools were bounded public exports: the original forty HotpotQA validation records plus one hundred additional dataset-server records at offset forty, and the first 128 records of the author-linked 2Wiki development raw export. This procedure randomizes selection within those pools; it does not establish a probability sample of a complete benchmark release.
The original CRAVE checkpoints for seeds 17, 29, and 43 were loaded without retraining. The confidence threshold, backbone, action definitions, 512 generated-token budget, one retrieval and one verification allowance, and deployment λ = 0.1 were unchanged. CRAVE, confidence, the fixed schedule, and the LLM router shared a 687-passage corpus constructed without answer labels from the original partitions and new question contexts. The larger corpus and new question set distinguish this protocol from the original pilot; the two result sets are not pooled into one estimate. No additional ablations or held-out value-oracle states were collected in this follow-up.
The test completed 480 episodes: forty questions multiplied by three seeds and four methods. Seeds were averaged within question before task-cluster bootstrap intervals were computed using ten thousand resamples. Paired comparisons used ten thousand random sign permutations with an add-one correction [26], because each dataset has twenty clusters. Holm correction covered a separate family of eighteen exploratory tests: two datasets, three comparators, and exact match, generated tokens, and normalized cost. This post-pilot follow-up was motivated by the earlier observations and is not presented as an independently preregistered confirmatory study.

9 Discussion and limitations
9.1 Interpreting the negative result
The expanded evaluation identifies an allocation failure: the learned controller performs about five reasoning calls per episode while confidence usually performs one. Additional generation was widespread across questions, but the accuracy differences were concentrated in one question per dataset. This pattern is consistent with overvalued continuation or weak stopping decisions. The current observations cannot distinguish training scarcity, noisy branch targets, continuation-policy mismatch, and inadequate state features as causes. A diagnostic result therefore guides the next experiment without establishing a causal explanation.
The framework may assign excessive value to continued reasoning when noisy training successes are not representative of held-out states. The original three-state diagnostic is consistent with optimistic predictions, but it does not establish a general overestimation mechanism. Similarly, a fixed λ and sparse budget support can leave a learned utility surface insufficiently constrained. The appropriate response is to test these explanations on development data rather than change evaluation settings after observing the held-out outcome.
9.2 Statistical and data limitations
The original six-question pilot cannot support a general benchmark conclusion. The expanded test adds forty fresh questions selected randomly from bounded record pools, but it remains a small post-pilot study rather than a representative full-benchmark evaluation. First-record selection is not a probability sample; three seeds do not increase the number of questions. Wide accuracy intervals and coarse permutation tests make population-level effects unidentifiable here. The raw exports and incomplete evaluator equivalence further restrict comparability. Pretraining contamination of the base model cannot be excluded from public factual QA data.
The pooled corpus contains benchmark passages from evaluation questions. This avoids answer-label leakage into the policy but creates transductive evidence availability. A full Wikipedia retrieval study could yield different costs, support coverage, and action preferences. Multi-hop answer correctness alone also does not demonstrate connected reasoning, a concern that motivates the MuSiQue dataset design [11].
9.3 Executor and estimand limitations
Quantization, non-thinking mode, bounded public summaries, a single same-model verifier, capped evidence, and conservative token reservations define a particular action system. A controller evaluated with hidden-state features, longer internal reasoning, independent verification, or another backbone would face different transitions and costs. The pilot provides no invariance result across these choices.
The learned values refer to μ0 continuation, whereas deployment uses the learned controller. This continuation mismatch is deliberate to preserve one label estimand across collection rounds, but it can limit policy improvement. Two rounds of changed visitation do not prove convergence. Ordered interaction targets use feasible common replicates and sparse checkpoint coverage; missing or ineligible pairs constrain what the auxiliary head can learn.
Latency includes measured action and controller overhead together with the cache convention. It is useful for tracing this execution but is not a strict service deadline or a standardized hardware comparison. Neither deployment amortization of offline labels nor net financial savings has been established. The physical cost of generating labels remains relevant even when a learned policy eventually reduces online cost.
9.4 Interpretation of statistical evidence
A nonsignificant accuracy comparison is not evidence of equivalent policies. No equivalence margin was specified, and the accuracy intervals admit changes that could matter in deployment. Pointwise bootstrap intervals and Holm-adjusted sign-randomization tests address sampling uncertainty and a corrected null comparison, respectively. Sign-randomization additionally requires exchangeability under the tested null, or a suitable symmetry assumption for paired differences. Questions were not randomized to policies, and no design-based causal treatment effect is claimed. Multiplicity correction handles the declared comparisons, not the broader adaptivity of a follow-up motivated by an inspected pilot.
The engineering implication is to inspect the resource vector before choosing a scalar utility. Fixed verification adds 0.5 to the implemented normalized cost, whereas output generation is divided by 4096. A policy can therefore lower that composite score while consuming more tokens. Cost-reference sensitivity, input-token charging, and cold latency should be specified for the intended deployment before optimizing efficiency. Reweighting existing trajectories characterizes those recorded trajectories; it does not show how a controller behaves after retraining or deployment with new preferences.
10 Requirements for broader evaluation
A complete evaluation should distinguish six questions: whether the controller improves quality and cost jointly, whether matched targets help when label quantity and action coverage are equal, whether delayed returns matter, whether ordered interactions help, whether budgets generalize, and whether behavior transfers. 11 Conclusion
CRAVE makes reasoning, retrieval, verification, and stopping comparable through matched action interventions and policy-conditioned return-to-go labels. Its executor guarantees compliance with the implemented hard resource caps when backend caps hold, while prediction quality determines how productively those resources are used. On the expanded 40-question test, CRAVE spent about four times the output tokens of a confidence rule. Paired accuracy differences were small, concentrated in one question per dataset, and not significant after multiplicity correction. Cost components explain why a weighted composite score can favor CRAVE over a verification-heavy schedule even when its generated-token consumption is higher. The contribution is a reproducible action-valuation framework and a documented failure case for learned allocation at small training scale. Coverage-matched supervision, development-only selection, larger official benchmark samples, and multiple backbones are needed to test whether the formulation can deliver an efficiency advantage.

Appendix A Executable procedure
Algorithm 1 specifies the labeling and deployment procedure used in the pilot. Gold labels are confined to the training scorer and held-out evaluator. The analytical oracle follows the labeling procedure on held-out states only after training.
1  Construct and checksum task partitions and the common label-free passage corpus. Define action caps, budget rules, utility reference scales, and μ0 before evaluation.
2  For each training task, save an initial checkpoint and selected collector-visited checkpoints. Persist them before starting branch generation.
3  For each saved state and eligible action, restore and hash-check the full state, assign a common replicate seed, force the action, and continue with μ0 until STOP or the finite executor limit.
4  Score the terminal candidate offline and record actual future resource consumption. Repeat for K = 3. Generate feasible pair and empty-intervention records for selected interaction checkpoints.
5  Average branch targets for each state and action at each training λ. Create masks for missing actions and pair contrasts. Fit the shared controller on training records only.
6  Collect another visitation round with the μ0 and learned-controller mixture while retaining μ0 for every label continuation. Aggregate both rounds and fit the final seeded variants.
7  Evaluate fixed settings on held-out tasks. Select only feasible actions. Log all output, input, tool, and timing counters, final candidates, and action histories.
8  Recompute task metrics, pair observations by task, bootstrap task clusters, apply exploratory corrections, verify artifact checksums, and report negative as well as positive findings.
